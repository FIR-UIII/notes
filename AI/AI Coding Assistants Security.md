# Безопасность AI-ассистентов разработки

Область: агенты и ассистенты в IDE и CLI (Claude Code, Cursor, GitHub Copilot, Codex CLI, Gemini CLI, Windsurf, Amazon Q и т.п.), а также AI-агенты в CI/CD (ревью PR, авто-фиксы).
Это частный случай [Agent Security](Agent%20Security.md), но с особой поверхностью атаки: агент работает **на машине разработчика с его правами и секретами** и читает недоверенный контент (чужие репозитории, issues, зависимости).

---

## Угрозы и примеры

| Угроза | Пример |
|---|---|
| Prompt injection через содержимое репозитория | инструкции в README, комментариях, issues, PR, документации зависимостей заставляют агента выполнять команды или сливать секреты |
| Rules-file backdoor | скрытые Unicode-символы в `.cursorrules`, `AGENTS.md`, `CLAUDE.md`, `copilot-instructions.md` (Pillar Security, 2025) |
| Автоисполнение конфигов проекта | клонированный репозиторий приносит `.mcp.json`, hooks, `.vscode/tasks.json`, настройки агента, которые запускают команды при открытии. По этому классу у ряда ассистентов были CVE |
| Атакующий использует локальный AI CLI | вредонос в npm-пакете Nx («s1ngularity», 2025) запускал установленные AI CLI с флагами обхода подтверждений для поиска секретов и кошельков |
| Компрометация самого ассистента | в расширение Amazon Q для VS Code попал промпт на удаление данных (2025) |
| Slopsquatting | модель предлагает несуществующий пакет, атакующий его регистрирует |
| Чтение секретов | агент читает `.env`, `~/.aws/credentials`, `~/.ssh`, токены IDE и отправляет их в контекст или наружу |
| YOLO-режим | `--dangerously-skip-permissions`, auto-approve всех команд на хосте |
| Небезопасный сгенерированный код | уязвимости и устаревшие API в коде, принятом без ревью |
| AI-агенты в CI | агент, запускаемый на `issue_comment` / `pull_request_target` с write-токеном, получает prompt injection из заголовка issue |

## Требования

### DEV-A. Политика и инструменты
- [ ] **DEV-01** `MUST` Утверждённый список ассистентов и тарифов: корпоративные планы без обучения на коде, с понятным retention, SSO и централизованной политикой (managed settings).
- [ ] **DEV-02** `MUST` Определено, какие репозитории и данные можно обрабатывать облачными ассистентами, а для каких нужны только self-hosted модели.

### DEV-B. Разрешения и изоляция
- [ ] **DEV-03** `MUST` Режим без подтверждений (auto-approve / YOLO) на хостовой машине разработчика запрещён. Он допустим только в одноразовой песочнице (devcontainer / VM / cloud sandbox) без секретов и с egress allowlist.
- [ ] **DEV-04** `MUST` Deny-правила на чтение секретов: `.env*`, `~/.ssh`, `~/.aws`, `~/.config/gcloud`, `~/.kube`, `~/.docker/config.json`, `*.pem`, `*.key`, хранилища токенов IDE/CLI.
- [ ] **DEV-05** `MUST` Allowlist команд вместо blocklist. Опасные команды (`curl | sh`, `rm -rf`, `git push --force`, публикация пакетов, `kubectl` к prod) всегда требуют подтверждения.
- [ ] **DEV-06** `SHOULD` Встроенный OS-sandbox ассистента (там, где он есть) включён. Сетевой доступ агента ограничен.
- [ ] **DEV-07** `MUST` На машинах разработчиков нет долгоживущих prod-учёток. Токены для агента — fine-grained, read-only по умолчанию, с коротким сроком.

### DEV-C. Доверие к репозиторию
- [ ] **DEV-08** `MUST` Проектные MCP-серверы, hooks и задачи из клонированного репозитория не включаются автоматически, нужно явное доверие к workspace.
- [ ] **DEV-09** `MUST` Файлы конфигурации агентов (`.mcp.json`, `.claude/`, `.cursor/`, `.vscode/`, `.github/copilot-instructions.md`, `AGENTS.md`, `CLAUDE.md`, `.cursorrules`) закреплены в CODEOWNERS и проходят обязательное ревью.
- [ ] **DEV-10** `MUST` Pre-commit и CI проверяют эти файлы (и весь репозиторий) на невидимые Unicode-символы (Tag, zero-width, bidi).
- [ ] **DEV-11** `SHOULD` Работа с недоверенными репозиториями (чужие PR, сторонние проекты, CTF) ведётся только в изолированной среде.

### DEV-D. Зависимости и код
- [ ] **DEV-12** `MUST` Пакеты, предложенные ассистентом, проверяются: существование, репутация, возраст, мейнтейнеры. Установка идёт через внутренний registry-прокси.
- [ ] **DEV-13** `SHOULD` Карантин свежих версий (minimum release age) на registry-прокси или в менеджере пакетов.
- [ ] **DEV-14** `MUST` AI-сгенерированный код проходит те же SAST, SCA, secret scan и ревью человеком. Авто-merge AI-PR запрещён.
- [ ] **DEV-15** `SHOULD` AI-авторство помечается (trailer `Co-Authored-By`, метка PR) для аудита и метрик качества.

### DEV-E. AI-агенты в CI/CD
- [ ] **DEV-16** `MUST` Агент в CI, который обрабатывает недоверенный ввод (issues, комментарии, PR из форков), работает с `permissions: read-all` и без секретов. Действия на запись выполняет отдельный шаг после проверки.
- [ ] **DEV-17** `MUST` Не запускать агентов с write-токеном на `pull_request_target` и `issue_comment` от внешних авторов.

### DEV-F. Обнаружение
- [ ] **DEV-18** `SHOULD` EDR и правила обнаружения: запуск AI CLI неинтерактивными процессами (postinstall-скрипты, CI), флаги обхода подтверждений, массовое чтение файлов секретов.
- [ ] **DEV-19** `SHOULD` Журналы сессий агентов (команды, файлы, сетевые обращения) экспортируются (OTel) для расследований.
