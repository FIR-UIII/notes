# Безопасность дообучения: fine-tuning, LoRA/PEFT, merge

Область: подготовка датасетов, дообучение (full FT, LoRA/QLoRA, DPO/RLHF), распространение и загрузка адаптеров, multi-LoRA serving, слияние моделей (mergekit), дистилляция.
Связанные файлы: [Model & Runtime](Model%20&%20Runtime%20Security.md), [MLSecOps & AIBOM](MLSecOps%20&%20AIBOM.md).

---

## Угрозы

| Угроза | Суть / пример |
|---|---|
| Отравление данных и backdoor | небольшой процент отравленных примеров вшивает триггер. Backdoor может пережить последующее safety-обучение (Anthropic, «Sleeper Agents», 2024) |
| Деградация safety | дообучение даже на безобидных данных снимает часть выравнивания (Qi et al., 2023) |
| Emergent misalignment | узкое дообучение (например, на небезопасном коде) даёт широкое нежелательное поведение (Betley et al., 2025) |
| Запоминание данных | модель выдаёт PII, секреты и фрагменты обучающих данных |
| Вредоносный адаптер | LoRA из публичного хаба содержит backdoor. Pickle-адаптер (`adapter_model.bin`) даёт RCE при загрузке |
| Динамическая загрузка адаптеров | runtime API загрузки LoRA (vLLM `/v1/load_lora_adapter`) позволяет подставить произвольный адаптер |
| Подмена адаптера тенанта | в multi-LoRA serving выбор адаптера параметром запроса без авторизации |
| Наследование при merge | слитая модель наследует backdoor любого из родителей |
| Датасеты как код | скрипты загрузки датасетов и `trust_remote_code` для `datasets` |

## Требования

### FT-A. Данные
- [ ] **FT-01** `MUST` У каждого датасета зафиксированы происхождение, лицензия и правовое основание (особенно для ПДн и пользовательских данных prod), datasheet и владелец.
- [ ] **FT-02** `MUST` Датасеты версионируются и хешируются (DVC, lakeFS, хеши в AIBOM). Обучение идёт только на зафиксированной версии.
- [ ] **FT-03** `MUST` Перед обучением датасет сканируется на секреты (gitleaks/trufflehog — особенно для датасетов из кода и логов) и PII. Найденное удаляется или маскируется.
- [ ] **FT-04** `MUST` Доступ к обучающим данным по RBAC. Запись в утверждённый датасет только через ревью.
- [ ] **FT-05** `SHOULD` Скрининг отравления: дедупликация, поиск аномальных примеров, повторяющихся редких токенов и триггер-паттернов, проверка вклада отдельных источников.
- [ ] **FT-06** `MUST` Датасеты из внешних хабов загружаются без исполнения кода: только форматы данных (parquet/jsonl/arrow), `trust_remote_code=False`.
- [ ] **FT-07** `SHOULD` Для чувствительных данных — differential privacy (DP-SGD) или как минимум canary-тесты на запоминание.

### FT-B. Окружение обучения
- [ ] **FT-08** `MUST` Обучение идёт в изолированном окружении: egress только к внутренним зеркалам, отдельная identity у задачи, секреты не в переменных окружения ноутбука, зависимости закреплены.
- [ ] **FT-09** `MUST` Чекпоинты и итоговые веса сохраняются в safetensors в registry с контролем доступа. Промежуточные чекпоинты защищаются так же, как финальные.
- [ ] **FT-10** `SHOULD` Пайплайн обучения выпускает provenance-аттестацию (in-toto/SLSA): какой код, какие данные (хеши), какая базовая модель и гиперпараметры.

### FT-C. Адаптеры (LoRA/PEFT)
- [ ] **FT-11** `MUST` Адаптеры берутся только из доверенных источников и только в safetensors. Проверяются хеш и подпись.
- [ ] **FT-12** `MUST` Адаптер в AIBOM привязан к хешу базовой модели. Адаптер загружается только на ту базовую модель, для которой утверждён.
- [ ] **FT-13** `MUST` В prod выключена динамическая загрузка адаптеров (`VLLM_ALLOW_RUNTIME_LORA_UPDATING` не включён, эквиваленты в других runtime). Набор адаптеров задаётся статически в конфиге развёртывания.
- [ ] **FT-14** `MUST` Выбор адаптера в запросе авторизуется: тенант может использовать только свои адаптеры. Имя адаптера проверяется по allowlist, а не используется как путь.
- [ ] **FT-15** `MUST` Сторонний адаптер перед допуском проходит ту же оценку, что и новая модель (FT-D).

### FT-D. Оценка перед релизом
- [ ] **FT-16** `MUST` Safety-регресс относительно базовой модели: jailbreak и вредный контент (garak, promptfoo, PyRIT, HarmBench-подобные наборы). Ухудшение выше порога блокирует релиз.
- [ ] **FT-17** `MUST` Тест на запоминание: извлечение canary-строк, PII и секретов из обучающего набора.
- [ ] **FT-18** `SHOULD` Поиск backdoor и триггеров: поведенческое тестирование на редких токенах и фразах, сравнение с базовой моделью, проверка на emergent misalignment вне целевого домена.
- [ ] **FT-19** `MUST` Слитая (merged) или квантизованная модель — это новый артефакт: новый хеш, запись в AIBOM, полная повторная оценка.

### FT-E. Fine-tuning как сервис
- [ ] **FT-20** `SHOULD` Если вы предоставляете дообучение клиентам: модерация загружаемых датасетов, safety-оценка результата перед выдачей, изоляция адаптеров и данных по тенантам, удаление по запросу.
