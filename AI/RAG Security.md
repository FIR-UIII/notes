# Безопасность RAG

Область: конвейер Retrieval-Augmented Generation. Включает загрузку источников, парсинг, чанкинг, эмбеддинги, векторную БД (Qdrant, Milvus, Weaviate, Chroma, pgvector, OpenSearch), поиск, переранжирование и подстановку в контекст. Сюда же относятся GraphRAG, web-search RAG и семантические кеши.
Связанные файлы: [LLM Application Security](LLM%20Application%20Security.md), [Agent Security](Agent%20Security.md).

---

## Угрозы

| Угроза | Суть |
|---|---|
| Косвенная prompt injection | инструкции в документах базы знаний: белый текст, комментарии, скрытые PDF-слои, alt-текст, метаданные |
| Отравление базы знаний | несколько специально составленных документов надёжно подменяют ответ на целевые вопросы (PoisonedRAG, 2024) |
| Обход контроля доступа | поиск идёт от сервисного аккаунта по всему индексу, и пользователь получает фрагменты документов, к которым у него нет доступа |
| Утечка между тенантами | общий индекс или коллекция, фильтр по тенанту на стороне приложения можно обойти |
| Инверсия эмбеддингов | по векторам восстанавливается исходный текст (vec2text), поэтому эмбеддинги так же чувствительны, как исходник |
| Открытая векторная БД | Chroma, Qdrant, Milvus по умолчанию часто без аутентификации |
| Устаревшие и «зомби»-данные | документ удалён или права отозваны в источнике, а чанки остались в индексе и кешах |
| Уязвимости парсеров | PDF, Office, HTML разбираются сторонними библиотеками |
| SSRF через коннекторы | web-fetch, crawler-ы, URL из документов |
| Утечка через семантический кеш | ответ, закешированный для одного пользователя, отдаётся другому на похожий вопрос |

## Требования

### RAG-A. Загрузка (ingestion)
- [ ] **RAG-01** `MUST` Источники для индексации утверждены (allowlist) и имеют владельца. Пользовательская загрузка в общий индекс — отдельный поток с модерацией.
- [ ] **RAG-02** `MUST` У каждого чанка есть метаданные происхождения: источник, ID документа, владелец, хеш, время загрузки, классификация, **ACL источника**.
- [ ] **RAG-03** `MUST` Очистка при загрузке: удаление скрытого текста (нулевой размер или цвет фона, скрытые слои), HTML-комментариев и скриптов, невидимых Unicode-символов (Tag, zero-width, bidi). Документы с аномалиями помечаются для ревью.
- [ ] **RAG-04** `MUST` Парсинг идёт в изолированном процессе или контейнере без сети, с лимитами ресурсов и антивирусной проверкой файлов.
- [ ] **RAG-05** `MUST` Обнаружение PII и секретов при загрузке, обработка по политике данных (маскирование, исключение, отдельный индекс повышенной защиты).
- [ ] **RAG-06** `SHOULD` Корпус с высоким доверием (политики, регламенты) изменяется только через ревью. Контроль изменений проводится по хешам.
- [ ] **RAG-07** `SHOULD` Обнаружение отравления: выбросы в пространстве эмбеддингов, массовые почти-дубликаты, документы, похожие на «ответ на конкретный вопрос», резкий рост от одного автора.

### RAG-B. Контроль доступа
- [ ] **RAG-08** `MUST` Права проверяются **при поиске** как pre-filter в запросе к векторной БД (по ACL/группам из метаданных), а не постфильтрацией в LLM и не инструкцией «не показывай».
- [ ] **RAG-09** `MUST` Поиск выполняется в контексте identity конечного пользователя, а не сервисного аккаунта с полным доступом.
- [ ] **RAG-10** `MUST` Права синхронизируются с системой-источником (SharePoint, Confluence, файловые шары, Git) с заданным SLA на отзыв. Отзыв прав в источнике в разумный срок отражается в индексе.
- [ ] **RAG-11** `MUST` Изоляция тенантов: отдельная коллекция или namespace на тенанта, а для высокой чувствительности — отдельная БД или инстанс. Фильтр по тенанту принудительно добавляется на стороне сервера.
- [ ] **RAG-12** `MUST` Ключ семантического кеша и кеша ответов включает пользователя/тенант и контекст авторизации.

### RAG-C. Векторная БД
- [ ] **RAG-13** `MUST` Аутентификация и авторизация включены (API keys / RBAC в Qdrant, Milvus, Weaviate, Chroma; роли в PostgreSQL для pgvector). TLS. Доступа из интернета нет.
- [ ] **RAG-14** `MUST` Эмбеддинги классифицируются по уровню исходных данных: шифрование at rest, бэкапы с тем же уровнем защиты, журнал доступа.
- [ ] **RAG-15** `MUST` Векторная БД и модель эмбеддингов — в инвентаре и AIBOM, версии закреплены, обновления по SLA.

### RAG-D. Поиск и генерация
- [ ] **RAG-16** `MUST` Найденные фрагменты подставляются в контекст как **данные** (с разметкой источника), а не как инструкции. Применяются требования [LLM Application Security](LLM%20Application%20Security.md) LA-03, LA-10–LA-13.
- [ ] **RAG-17** `MUST` Ограничены top-k, размер чанка и общий объём подставляемого контекста.
- [ ] **RAG-18** `SHOULD` Ответ содержит ссылки на источники. Для критичных доменов проверяется обоснованность (groundedness), а ответ без источника отклоняется.
- [ ] **RAG-19** `MUST` Web-search RAG и crawler-ы: allowlist доменов, SSRF-защита (запрет приватных диапазонов и метаданных облака, перепроверка после редиректов), контент из интернета имеет наименьшее доверие.

### RAG-E. Жизненный цикл данных
- [ ] **RAG-20** `MUST` Удаление документа в источнике (в т.ч. по требованию субъекта ПДн — 152-ФЗ / GDPR) удаляет его чанки, эмбеддинги и записи в кешах. Процесс проверяем.
- [ ] **RAG-21** `SHOULD` Индекс версионируется. При смене модели эмбеддингов он полностью переиндексируется с повторным применением ACL.

### RAG-F. Мониторинг и тестирование
- [ ] **RAG-22** `SHOULD` Мониторинг аномалий поиска: перебор (enumeration) запросами, массовое извлечение, запросы к чужим тенантам, отказы pre-filter.
- [ ] **RAG-23** `MUST` Тесты перед релизом: пользователь A не может получить документы B; документ-ловушка с инструкцией не меняет поведение; удалённый документ не находится.
