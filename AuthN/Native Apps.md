Native App - клиентское приложение, которое:
* устанавливается и работает непосредственно на устройство пользователя (смартфон, планшет, десктоп)
* не работает внутри веб-браузера, но может вызывать системный браузер или webview
* не имеет полноценного бэк-сервера

Меры безопасности:
* Loopback Interface Redirection "http://127.0.0.1:{port}/{path}" for IPv4, and "http://[::1]:{port}/{path}" for IPv6 с TLS.
* Использование кастомных URI-схем (myapp://callback) допустимо, но несет риски перехвата другими локальными приложениями в ОС, зарегистрировавшими ту же схему + см. особенности https://www.rfc-editor.org/info/rfc8252/#appendix-B
* тип клиента public, даже если confidentional - все равно секрет храниться в приложении и даже если будет использовать хранилище ключей - это риск. поэтому даже конф.клиент следует рассматривать как публичный
* обязательное использование Authorization Code Flow + PKCE
* DPoP как рекомендация
* "state" и nonce - обязательные атрибуты для запроса аутентификации
* запрет WebView (CEF, Qt WebEngine, WebView2, WKWebView, UIWebView,  и т.д.) - использовать только системный браузер. Причины: наличие уязвимостей в них, возможность MITM, 0-day, возможность доступа к js рантайму из самого приложения, риск перехвата кук и сессии из проблем с изоляцией и т.п.
* Использование системных защищенных хранилищ (OS Keyring / Credential Manager). Для сохранения токенов приложение обязано использовать нативные механизмы операционной системы, обеспечивающие шифрование на уровне учетной записи пользователя:
Windows: Windows Credential Manager или DPAPI. macOS: Keychain Services API. Linux: Secret Service API (GNOME Keyring / KWallet) через libsecret.
* Короткое время жизни токенов Access Token: в пределах 5 минут, Refresh Token: 30 мин + Refresh Token Rotation, на стороне OIDC-провайдера (например, Keycloak) должна быть включена ротация рефреш-токенов. При каждом обновлении
